## 演習

  - 「3レベル」の質問：`search_glossary({'query': '3レベル'})` の1回
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})` と `search_glossary({'query': 'QLoRA'})` の2回。docstring の「query には調べたい用語を1つだけ入れる」に従い、用語を分けて1回のリクエストの中で並べて呼んでいた。
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 上の質問はどれも `requests=2` であった。1回目でツールを呼ぶと決め、ツールの結果を受け取った2回目で回答を作る。
  - ツールを2回呼んだ LoRA/QLoRA の質問でも `requests=2` のままであった。2つの呼び出しが同じリクエストの中で出されたためである。
  - 入力トークンは、素のLLMが 122 であるのに対し、エージェントは 1,653〜2,066 であった。指示・ツールの説明・ツールの結果を毎回モデルに渡すぶん、1つの質問のコストは上がる。
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int)` を追加した。docstring には次の3点を書いた。
    - 使う場面：確認問題・クイズ・復習の問題を求められたとき
    - 結果の使い方：答えは用語集の定義なので、問題文を自分で作らずこの結果を使って出題する
    - 用語が無い回（`lecture=0` など）の扱い：例外ではなく、問題を作れる回の一覧を返す
  - `INSTRUCTIONS` にも「確認問題を求められたら make_quiz を使い、答えは問題のあとに分けて示す」を足した。
  - 「第2回の内容から確認問題を1問出して」で `make_quiz({'lecture': 2})` が呼ばれた（`requests=2`）。2回実行すると「教師ありファインチューニング（SFT）」と「量子化」の別々の問題が出た。どちらも、答えは問題のあとに分けて示されていた。

## 宿題

- 取り組んだレベル：実装
- やったこと：
  - **ツール本体**：`app/tools.py` に `save_learning_log(title, content, lecture=None)` を追加した。`learning_log/` に `YYYYmmdd-HHMMSS_<題>.md` として、見出し・日時・関係する回・本文を Markdown で保存する。
    - 引数の説明は docstring の `Args:` 節に書いた。Pydantic AI はこれを JSON Schema の `description` に入れるので、`--list-tools` で各引数の説明がモデルに渡っていることを確認できる。
  - **ツール側の防御**：取り消しにくい操作なので、ツールの中でも次の4点を守るようにした。
    - 既存ファイルは上書きしない（`open(..., "x")` で開き、同じ名前なら `-2` などを付ける）
    - 題からファイル名を作るときに `/` や `.` を置き換える
    - 保存先が `learning_log/` の外に出ないことを `resolve()` で確かめる
    - 空の引数・長すぎる本文・`lecture < 1` のときは保存せず、理由をモデルに返す
  - **登録**：`app/agent.py` で `agent.tool_plain(tools.save_learning_log, requires_approval=True)` と登録し、`output_type=[str, DeferredToolRequests]` にした。
  - **承認の流れ**：CLI に `run_with_approval` を入れた。
    1. `run_sync(question)` の結果が `DeferredToolRequests` なら、`approvals` の呼び出しごとに、ツール名と引数（保存される題・回・本文）を表示して `[y/N]` で聞く。
    2. 答えを `DeferredToolResults(approvals={tool_call_id: True | ToolDenied(...)})` にまとめ、`message_history=result.all_messages()` と一緒に `run_sync` をもう一度呼ぶ。
    3. `usage=result.usage` を引き継ぎ、`[usage]` の `requests` が承認の前後を合わせた LLM 呼び出し回数になるようにした。
  - **拒否側に倒す設計**：
    - `y`/`yes` 以外の入力（空 Enter・`はい` など）と、入力できない環境（EOF）は拒否として扱う。
    - 拒否したときは `ToolDenied` に「保存をやり直さず、保存しなかったことを伝えること」というメッセージを入れてモデルに返す。`INSTRUCTIONS` にも同じことを書いた。
    - それでもモデルが保存を呼び続ける場合に備え、承認のやり取りは最大3回で打ち切る。
  - **テスト**：`tests/test_learning_log.py` を追加した（API キー不要）。次のことを確かめる。
    - 保存されるファイルの中身が正しい
    - 既存のファイルを上書きしない
    - 保存先の外に出ない
    - 不正な引数では保存しない
    - 承認前は何も書かれない
    - 承認すると書かれる
    - 拒否・EOF では書かれない
    - 承認のやり取りが上限で止まる
- 結果：
  - `uv run pytest -q` で 35 件すべて通った。
  - 「LoRAとQLoRAの違いを調べて、学習ログに保存して」を `--trace` 付きで2回実行した。

    | 承認 | ツール呼び出し | `requests` | `tool_calls` | 入力トークン | 保存 |
    |---|---|---|---|---|---|
    | y | `search_glossary`×2 → `save_learning_log` | 3 | 3 | 3,619 | `learning_log/20261109-050430_LoRAとQLoRAの違い.md` ができた |
    | n | `search_glossary`×2 → `save_learning_log` | 3 | 2 | 3,607 | 何もできなかった |

  - 流れは想定どおりであった。モデルは用語を2つ検索し、その結果から `title='LoRAとQLoRAの違い'`、`lecture=2` と本文を作って `save_learning_log` を呼んだ。実行はここで止まり、承認画面に引数が表示された。
  - `requests=3` の内訳は次のとおりである。usage が承認の前後で引き継がれていることも、これで確認できた。
    1. 検索を決める
    2. 保存を決める（ここで承認待ちになる）
    3. 承認の結果を受けて回答を作る
  - 拒否したときの `tool_calls=2` は、拒否された呼び出しが実行されずに数えられていないことを示している。モデルは保存を呼び直さず、回答の冒頭で「保存の承認が得られなかったため保存しなかった」と伝えた。
  - 意図しない入力で拒否される場面も一度あった。最初にコマンドをまとめて貼り付けたとき、`[y/N]` に後続のコマンドの行が入力として読み込まれた。それは `y` ではないので拒否になり、保存されなかった。うっかりした入力では保存されないという、拒否側に倒した設計がそのとおりに働いた例である。
- 気づき・疑問：
  - **承認は run の外で行う**：`requires_approval=True` を付けたツールは実行されず、run は一度 `DeferredToolRequests` を返して終わる。承認はツールの中で `input()` を呼ぶのではなく、run の外で人が判断し、会話の履歴と一緒に結果を渡し直す形になっている。そのため、CLI でも Web でも、承認の画面を差し替えるだけで同じエージェントを使える。
  - **承認にはコストがかかる**：保存を伴う質問の入力トークン（約 3,600）は、保存しない同じ質問（2,066）の約 1.75 倍であった。保存の判断のために LLM の呼び出しが1回増え、その呼び出しでも、それまでの会話（検索結果を含む）をすべて送り直すためである。
  - **承認画面で見るべきなのは、モデルが作った引数である**：実際に本文を見ると、用語集の定義にない語（「アダプタ」「大幅に」）が少し足されていた。また、本文の先頭に `### LoRAとQLoRAの違い` と見出しを入れていたため、ファイルの中では題が `#` と `###` の二重になった。後者は、docstring に「content に見出しは入れない」と書けば直せそうである。
  - **日時が UTC になる**：Codespaces のタイムゾーンは UTC なので、記録の日時とファイル名は UTC になった（`+00:00`）。日本時間で残したい場合は、タイムゾーンを明示する必要がある。
  - **承認だけに頼らない**：承認は利用者による最後の防御であって、それだけに頼るのは危うい。ツール側でも、上書きしない・保存先の外に出ない・長さを制限する、という防御を入れた。
  - **疑問**：今回は拒否されたあとにモデルが保存を呼び直すことはなかったが、`ToolDenied` のメッセージを空（既定の英文）にした場合も同じになるのかは確かめていない。比べてみたい。
